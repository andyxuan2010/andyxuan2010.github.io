# Security policy

## Reporting a vulnerability

Do not disclose suspected vulnerabilities, credentials, personal information,
or exploit details in a public issue.

Use GitHub's **Report a vulnerability** option on the repository Security tab.
If private vulnerability reporting is unavailable, contact the repository owner
through the private contact method listed on their GitHub profile.

Include the affected page or workflow, reproduction steps, impact, and a
suggested remediation when known. Remove secrets and personal data from logs and
screenshots. The maintainer will acknowledge the report, assess severity, and
coordinate disclosure and remediation.

## Supported version

The current `main` branch and the site it publishes are supported. Historical
commits and copied source documents are retained for reference but are not
maintained as separate releases.

## Credential exposure

If a credential is found, revoke or rotate it before removing it from the
repository. Repository history and workflow logs must be treated as exposed
until the credential owner confirms rotation.
