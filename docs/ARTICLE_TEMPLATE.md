# Replace with a clear article title

Write a short introduction that explains the problem, intended audience, and expected outcome.

## Purpose

Explain why the guidance exists and when readers should use it.

## Recommended approach

- Describe the preferred design or procedure.
- State important security and governance considerations.
- Identify dependencies, assumptions, and meaningful tradeoffs.

## Validation

Explain how readers can prove that the implementation or control works.

## Operational considerations

Document ownership, monitoring, failure handling, recovery, and cost considerations.

## Related topics

Link to related canonical Markdown articles using relative Markdown links.

## Related Repos

This section is optional. Omit the heading when no repository directly supports the article. When used, verify every repository, link to its canonical URL, and explain its relevance in one sentence; do not add generic organization or profile links.

- [owner/repository](https://github.com/owner/repository) — describe the implementation, example, module, or automation that relates to this article.
