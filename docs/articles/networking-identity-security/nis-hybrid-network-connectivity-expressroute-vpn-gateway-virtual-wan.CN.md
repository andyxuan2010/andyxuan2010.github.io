# 混合网络连接 — ExpressRoute、VPN 网关和 Virtual WAN

## 目的和设计立场

此体系结构定义了用于将 Azure 连接到数据中心、分支机构、远程用户和其他虚拟网络的批准选择和弹性模式。 Azure ExpressRoute、VPN 网关和 Virtual WAN 解决网络连接、路由和中转问题。它们**不**实现应用集成逻辑、业务工作流程、API 中介、消息处理、数据转换或业务操作授权。

使用 ExpressRoute 进行基于私有提供商的连接，其中关键企业工作负载需要比公共 Internet 连接能够提供的更一致的网络路径、延迟配置文件和可靠性模型。使用 VPN 网关通过公共 Internet 进行加密的站点到站点或点到站点连接，特别是对于小型部署、初始连接、远程管理或单独设计的 ExpressRoute 备份路径。使用 Virtual WAN 实现跨多个分支机构、虚拟网络、中心和远程用户的集中式、Microsoft 管理的连接和路由。

对于关键环境，默认弹性模式 SHOULD 将 ExpressRoute 作为主要路径，将站点到站点 VPN 作为单独的故障转移路径。路径 MUST 足够独立，可以提供有意义的保护：单独的客户边缘设备、提供商或电路（如果可行）、终端资源、电源和设施依赖性、路由策略、监控和经过测试的故障转移。共享一个不受监控的设备、运营商或物理设施的两个逻辑连接不是独立的恢复路径。

## 范围和设计成果

当工作负载或平台需要执行以下操作时，请使用此模型：

- 将企业 WAN 或数据中心私下连接到 Azure；
- 通过公共互联网建立加密的站点到站点连接；
- 为经批准的远程用户或管理员提供点到站点的访问；
- 通过集中管理的中转网络连接许多分支机构、虚拟网络、区域和远程用户；
- 在本地网络和 Azure 落地工作区之间传输流量；
- 为关键混合工作负载创建主要且单独设计的备份路径；
- 在混合路径上应用路由域、前缀、检查和传播控制；或者
- 向仍需要工作负载身份和应用授权的服务公开私有网络路径。

目标结果是：

- 每个电路、隧道、网关、中心、附件、路由域和客户边缘都有一个所有者和生命周期状态；
- 地址空间、BGP 通告、路由传播、下一跳和故障行为是明确的并经过测试；
- 关键流量有一条幸存路径，可以在声明的故障后承载所需的负载；
- ExpressRoute、VPN 网关和 Virtual WAN 是根据不同的连接需求而选择的，而不是被视为可互换的产品；
- 连接性与应用集成分离，不会成为隐藏的业务处理层；
- 私有 DNS、防火墙、安全组、身份和应用授权仍然是端到端访问设计的一部分；和
- 监控和运行手册使路由、隧道、电路、网关、延迟、丢失、容量和故障转移状态可操作。

## 背景和决策驱动因素

混合流量通常承载比普通 Internet 访问对可达性、延迟、数据包丢失、路由收敛和中断持续时间更敏感的依赖性。网络路径可以将客户端连接到工作负载，但它不能证明客户端有权调用工作负载或应用可以安全地处理请求。

该决定的驱动因素是：

- **路径隐私：** 流量是否必须使用私有提供商或加密隧道路径而不是公共服务端点。
- **一致性和性能：** WAN 和 Azure 上所需的延迟、抖动、吞吐量、数据包丢失容限和路由稳定性。
- **弹性：**运营商、设施、边缘设备、网关、电路、区域、提供商和路由控制平面的故障域。
- **规模：** 分支机构、虚拟网络、远程用户、区域、路由前缀和安全域的数量。
- **操作：**组织是否可以操作客户端设备、BGP、隧道、证书、网关和路由策略。
- **安全性：** 加密、检查、前缀过滤、私有 DNS、默认拒绝分段、日志记录和最低权限管理。
- **地点：** 流量是否必须保持在区域、分支机构、数据中心、私有云或受监管边界附近。
- **成本和实现价值的时间：** 与 VPN 设置、带宽、网关、中心和出口成本相比，提供商电路交付时间和经常性成本。

## 服务选择

|要求 |首选服务或模式|为什么 |重要边界|
|---|---|---|---|
|关键的私营企业广域网连接 |ExpressRoute |基于提供商的私有连接，具有更受控制的路径和高吞吐量选项 |它仍然取决于客户 WAN、提供商、对等位置、网关、路由和工作负载控制 |
|较小的部署或初始混合连接 |站点到站点 VPN 网关 |公共互联网上的加密 IPsec/IKE 连接，设置难度更低 |互联网路径性能和运营商可用性是可变的；调整网关大小并测试 MTU、延迟、丢失和故障转移 |
|批准的远程用户访问 | VPN 网关点到站点 |使用受支持的协议和身份选项从单个客户端设备进行加密远程访问 | P2S 访问不能替代应用授权、设备状态或特权访问控制 |
| ExpressRoute 保护或站点不在专用线路上 |共存 ExpressRoute 和站点到站点 VPN |单独的网关和路径可以提供备份或到达 ExpressRoute WAN 外部的站点 |路由偏好、隧道健康状况、BGP、设备多样性和故障转移行为 设计 MUST 和测试 |
|许多分支机构、VNet、区域或远程用户 |Virtual WAN | Microsoft 管理的中心和路由降低了自管理的中转网络复杂性 |路由表、传播、安全检查、中心容量和流量路径仍然需要治理 |
|应用到应用的工作流程 | API、Service Bus、Logic Apps、Functions 或应用运行时 |提供契约、中介、持久性、编排或自定义代码 |网络可达性只是一个依赖项；它没有实现应用集成|

主要路径通过 ExpressRoute 进入 Azure。单独的站点到站点 VPN 路径使用独立的客户边缘和互联网连接，并且仍然可用于故障转移或不属于专用 WAN 的站点。当资产具有许多分支、VNet、ExpressRoute、VPN 或点到站点连接时，Virtual WAN 可以提供托管中转网络。当托管中转网络设计中无法提供所需的路由、检查或设备功能时，自管理中心 VNet 仍然适用。

连接平面连接到工作负载 VNet、共享服务、安全检查和私有服务访问。路由可达性 MUST 受到路由域和策略的约束。网络访问 MUST 与身份、安全控制、私有 DNS 和应用授权相结合。该图故意停在网络边界：此架构中没有服务执行应用集成逻辑。

## ExpressRoute

### 适当使用

ExpressRoute 通过连接提供商、云交换或支持的直接模型在企业 WAN 和 Microsoft 云服务之间提供私有连接。当工作负载或平台需要私有路径、一致的提供商管理的连接、高吞吐量或比基于互联网的 VPN 通常提供的更强的弹性和性能模型时，请使用它。

典型用途包括：
- 0 级或 1 级数据中心与生产 Landing Zone 的连接；
- 从企业 WAN 到 Azure 平台和工作负载网络的私有访问；
- 具有测量带宽和延迟要求的高吞吐量混合依赖性；
- 公共互联网传输不是公认的主要路径的受监管或敏感环境；
- 围绕独立对等位置设计的区域或多区域连接；和
- ExpressRoute 加上站点到站点 VPN 弹性模式中的主要路径。

ExpressRoute 本身不保证应用 SLO。有效路径包括客户 LAN 和 WAN、客户边缘路由器、提供商或交换机、ExpressRoute 电路、Azure 网关、Virtual WAN 中心或 VNet、路由策略、防火墙、DNS 和工作负载。测量整个路径并确定已声明故障场景的幸存路径的大小。

### 路由和弹性

在支持且适当的情况下，使用 BGP 进行动态路由交换。前缀通告和接受 MUST 按路由域、环境、区域和信任边界进行过滤。记录私有对等互连、路由限制、本地首选项、AS 路径行为、默认路由处理、路由汇总和故障转移首选项。

ExpressRoute 线路包括到提供商或对等位置处的 Microsoft Enterprise Edge 路由器的冗余连接，但客户端弹性仍然需要独立的边缘设备、链路、电源、设施和适当的提供商路径。对于关键或灾难恢复要求，请评估不同对等位置的两条电路以及单独的区域网关依赖性。一个位置的第二个连接可能无法防止设施、运营商或区域故障。

ExpressRoute 的辅助连接是一种冗余机制。除非容量和服务条款明确支持该操作模型，否则不要在为故障而保留的路径上计划持续的额外流量。测试电路、BGP 会话、网关、路由收敛以及电路、边缘、运营商、网关和区域故障下的工作负载行为。

### 安全和运营

私有连接并不是每种威胁模型中的加密。确定电路、提供商、数据分类和监管控制是否满足所需的保护；必要时添加应用层或网络层加密。独立应用路由过滤、防火墙检查、网络安全组、私有 DNS、基于身份的访问和日志记录。

网络平台团队 MUST 维护电路 ID、提供商联系人、对等位置、带宽、BGP 参数、IP 分配、网关 SKU 和区域配置、维护窗口、续订日期、路由策略、所有者和升级路径。监控电路状态、BGP 状态、路由计数、路由更改、吞吐量、延迟、数据包丢失、错误、网关运行状况和提供商事件。

## VPN 网关

### 站点到站点 VPN
使用站点到站点 VPN 通过公共 Internet 在本地或分支 VPN 设备与 Azure VPN 网关之间建立加密的 IPsec/IKE 连接。它应用于较小的部署、初始迁移、临时或低容量站点、没有 ExpressRoute 覆盖的站点以及单独设计的备份路径。

客户 VPN 设备 MUST 具有受支持的配置、外部可访问的地址、兼容的 IPsec/IKE 参数、稳定的时间同步和记录在案的所有者。首选网关 SKU 和设计支持的主动-主动和区域弹性配置。使用 BGP 进行动态路由交换，改善收敛和路由控制；否则，静态路由 MUST 进行版本控制、过滤和监控。

站点到站点 VPN 性能取决于互联网路径、客户设备、网关 SKU、隧道数量、加密、数据包大小和并发流量。建立吞吐量、延迟、抖动、数据包丢失、MTU、密钥更新行为和故障转移时间的测量限制。不要将成功的隧道状态视为每个应用路径都健康的证据。

### 点到站点 VPN

对需要私有网络访问的经批准的远程用户或个人客户端设备使用点到站点 VPN。将身份验证与批准的身份和特权访问控制集成。定义设备状态、用户组、路由范围、DNS 行为、分割隧道、会话持续时间、日志、撤销和支持边界。

点到站点访问 SHOULD 仅限于用户角色所需的资源和管理路径。 MUST NOT 仅仅因为用户已连接到网络就提供广泛的可达性。当用户需要一个应用而不是路由网段时，首选应用感知的私有访问。

### ExpressRoute 和 VPN 共存

对于关键环境，将 ExpressRoute 和站点到站点 VPN 部署为与单独的 ExpressRoute 和 VPN 网关资源共存的连接。 VPN 路径应使用独立的客户边缘、互联网提供商、地址路径和运营所有权（如果可行）。配置并测试路由首选项，以便正常流量使用预期的 ExpressRoute 路径，并且仅当满足定义的 ExpressRoute 运行状况和路由条件时，流量才会移动到 VPN 路径。

不要依赖单个手动更改的静态路由来执行故障转移。定义运行状况信号、BGP 或路由撤销行为、收敛预算、非对称路由控制、防火墙状态行为、应用重试行为和恢复过程。计划性故障恢复 MUST 避免路由振荡，并且在流量返回之前必须确认主路径稳定。

## Virtual WAN

Virtual WAN 是 Microsoft 管理的网络服务，用于跨分支机构、虚拟网络、ExpressRoute 线路、VPN 站点、点到站点用户和区域虚拟中心进行集中连接和路由。当资产具有足够的附件或路由域而自管理的中心辐射式中转网络会产生不必要的对等互连、路由表或操作复杂性时，请使用它。

Virtual WAN 可以提供：

- 具有托管路由的区域虚拟中心；
- 从 ExpressRoute 和 VPN 站点到中心的连接；
- 点到站点或远程用户连接；
- 用于工作负载和共享服务辐条的虚拟网络连接；
- 在路由策略允许的情况下，中心间和分支到分支的中转；
- 使用 Azure Firewall 或经批准的网络虚拟设备实现集中安全；和
- 多区域分支和 VNet 连接的通用框架。

Virtual WAN 不是授权服务、Application Gateway、消息代理、API Management 层或工作流运行时。其托管路由并没有消除对路由域、前缀过滤器、安全检查、私有 DNS、工作负载身份、应用授权、日志、容量规划和事件运行手册的需求。

### 路由表和传播

在连接网络之前定义路由域模型。至少要考虑生产、非生产、共享服务、安全检查、合作伙伴或外联网、受限、沙箱和恢复域。域之间的路由传播 MUST 默认被拒绝，除非记录在案的业务路径得到批准。

记录每个连接的关联和传播的路由表、静态路由、下一跃点、默认路由行为、安全提供程序插入、分支到分支行为、中心间行为和故障转移首选项。防止意外的生产到非生产可达性、检查绕过、默认路由泄漏以及未经批准的传递路径。

### 安全性和规模

当威胁模型需要集中检查时，使用 Security Hub 和 Azure Firewall 或批准的网络虚拟设备。确认东西向、分支到分支、中心间、互联网出口和分支流量是否经过预期的检查路径。状态检查需要对称路由和组件故障后足够的生存能力。

容量规划 MUST 包括中心计数、VNet 和分支连接、路由计数、吞吐量、并发流、中心间流量、防火墙容量、网关容量、点到站点用户和故障模式负载。在提交到中心拓扑之前验证当前的 Azure 限制和定价。托管控制平面减少了实施工作；它并没有消除设计或运营工作。

## 寻址、DNS 和路由

对所有 Azure、本地、分支、VPN 和合作伙伴前缀使用权威 IPAM。重叠地址空间 MUST 通过重新寻址、受控 NAT、代理或服务发布来解决。不要将广泛的永久 NAT 作为默认的企业设计。

混合 DNS 是第 0 层依赖项。定义公共权限、私有权限、转发、水平分割行为、私有端点区域、解析器位置、条件转发器、日志记录和恢复。按 IP 地址工作但按名称失败的路由不是健康的应用路径。

BGP 和路由表 MUST 被视为安全策略。过滤学习和通告的前缀，防止路由泄漏，定义默认路由所有权，监视路由计数和更改，并对意外传播发出告警。记录每个关键流量类别的预期路径，包括返回路径。

## 安全控制
- 将连接资源、网关、中心、路由策略、DNS 解析器、防火墙和共享网络服务保留在专用平台域中。
- 将最低权限 RBAC 应用于电路、网关、中心、连接、路由、防火墙和诊断管理。
- 在经批准的机密管理服务中保护 VPN 证书、共享密钥、设备凭证和自动化机密。
- 使用网络安全组、Azure Firewall 或批准的检查、私有端点和工作负载身份作为单独的控制。
- 对数据分类或协议需要网络路径之外的保护的应用有效负载进行加密。
- 限制管理平面访问已批准的管理路径并监控配置更改。
- 对流量、VPN、网关、防火墙和数据包故障排除日志中的敏感数据进行脱敏，同时保留足够的诊断证据。
- 在选择电路或传输之前，记录客户管理的加密、监管、数据驻留、提供商和合法拦截要求。

网络可达性 MUST NOT 被视为业务授权。应用团队仍然负责身份验证、授权、输入验证、租户隔离以及重试或重复请求的安全处理。

## 弹性和故障处理

主路径和备份路径 MUST 被建模为依赖图，而不仅仅是绘制为两条线。识别故障域：

- 客户边缘设备、电源、设施和本地 LAN；
- WAN 提供商、互联网服务、运营商、交换和对等位置；
- ExpressRoute 线路和 Microsoft Enterprise Edge 连接；
- VPN 设备、隧道、网关、公网 IP、证书；
- Virtual WAN 中心、中心间路径、路由表和安全提供商；
- Azure 区域、可用区、订阅、资源组和控制平面；
- DNS 解析器、私有区域、防火墙、网络虚拟设备和路由策略；和
- 工作负载、Application Gateway、私有端点、身份提供商和相关服务。

对于每个关键流量类别，定义：

- 正常路径和预期的路由偏好；
- 备用路径和激活它的故障信号；
- 最大收敛和恢复时间；
- 宣告故障后可用的容量；
- 有状态防火墙和 NAT 的预期行为；
- 对 DNS 和服务发现的影响；
- 应用超时、重试和连接池行为；和
- 恢复、故障回切、协调证据程序。

不要仅从网关状态来声明弹性。执行受控电路、运营商、边缘、隧道、网关、路由、防火墙、DNS、区域和工作负载测试。在代表性负载下进行测试，并确认幸存路径不会使依赖项过载或创建不对称路由。

## 性能和成本
测量端到端延迟、抖动、数据包丢失、吞吐量、MTU、连接建立、路由收敛和应用响应时间。 ExpressRoute 可能提供比公共互联网 VPN 更一致的路径，但应用结果仍然取决于每个网段和依赖性。 VPN 性能因互联网条件以及网关或设备容量而异。Virtual WAN 添加了托管中转网络和中心路由，可以简化操作，但它引入了中心、网关、防火墙、中心间和数据处理成本驱动因素。

成本估算 MUST 包括电路、提供商或交换费用、VPN 网关 SKU、ExpressRoute 和 VPN 网关资源、Virtual WAN 中心和连接、防火墙或 NVA 容量、公共 IP、出口、区域间流量、监控、支持、客户边缘设备、许可证、运营商多样性和运营人员配置。当中断成本、提供商交付时间或关键性需要更强的弹性时，不要仅根据每月基础设施价格来选择路径。

## 操作和生命周期

网络平台团队负责连接基线、地址分配、电路和隧道清单、网关和中心生命周期、路由策略、私有 DNS 集成、安全检查、监控、提供商协调恢复操作手册。工作负载团队负责其声明的流量路径、应用运行状况检查、身份和授权、依赖性限制和验证证据。安全和治理团队定义加密、分段、日志、数据保护和异常要求。

每个生产连接都应有一个操作记录，其中包含：

- 服务、电路、隧道、中心、网关和客户边缘标识符；
- 所有者、商业目的、环境、区域、路由域和数据分类；
- 提供商、设施、运营商、带宽、IP 范围、BGP ASN、对等地址和维护窗口；
- 网关 SKU、区域配置、隧道或电路冗余、防火墙路径和 DNS 依赖性；
- 预期延迟、吞吐量、丢失、路由计数、收敛和 SLO 阈值；
- 凭据、证书、密钥、轮换、更新和紧急访问程序；
- 监控仪表板、告警阈值、提供商联系人、升级和支持路径；和
- 计划的变更、续订日期、退役日期和经过测试的恢复证据。

至少监控：

- ExpressRoute 线路、连接、BGP 会话、路由计数、路由更改、带宽和数据包指标；
- VPN 隧道状态、IKE/IPsec 协商、密钥更新、数据包丢失、吞吐量、网关健康状况和点到站点会话；
- Virtual WAN 中心、连接、路由表传播、中心间、分支到分支以及网关运行状况；
- 防火墙或 NVA 吞吐量、流量计数、丢包、非对称路径指示器和剩余容量；
- DNS 查询成功、延迟、转发失败、私有区域更改和解析器运行状况；
- 跨关键路径的延迟、抖动、丢失、MTU、连接建立和应用综合探测；
- 未经授权的路由、前缀、网关、电路、隧道、防火墙、DNS 和 RBAC 更改；和
- 提供商维护、证书到期、订阅或配额压力以及事件状态。
运行手册应涵盖 ExpressRoute 电路丢失、提供商中断、BGP 撤销、VPN 隧道故障、证书或密钥过期、网关降级、Virtual WAN 路由传播错误、路由泄漏、DNS 故障、防火墙容量耗尽、非对称路由、重叠前缀、公共 IP 暴露以及受控故障转移或故障恢复。

## 验证

- [ ] 连接性与应用集成逻辑、工作流编排、API 中介、消息传递和业务授权不同。
- [ ] ExpressRoute、VPN 网关、Virtual WAN 或自管理 Hub 是从记录在案的隐私、性能、规模、弹性、位置、成本和运营要求中选择的。
- [ ] 关键环境具有 ExpressRoute 主路径和单独设计的站点到站点 VPN 备份路径，或具有同等证据的经批准的替代路径。
- [ ] 主路径和备用路径具有独立的客户边缘、提供商、设施、电源、寻址、终端资源和操作依赖性（如果可行）。
- [ ] ExpressRoute 线路、对等位置、提供商、BGP、网关、路由限制、带宽和故障域均已日志记录。
- [ ] VPN 站点到站点或点到站点配置、设备、IPsec/IKE 策略、身份、证书或密钥、网关 SKU 以及客户端或站点范围均已日志记录。
- [ ] 记录 Virtual WAN 中心、附件、路由表、传播、中心间路径、分支到分支行为、防火墙插入和容量。
- [ ] IPAM 权威，前缀不重叠，BGP 或静态路由被过滤和监控。
- [ ] 私有 DNS、转发、私有端点区域、防火墙路径、路由对称性和返回路径均在每个所需环境中进行测试。
- [ ] 网络可达性与工作负载身份、应用授权、租户隔离和数据保护控制相结合。
- [ ] 关键路径延迟、抖动、丢失、吞吐量、MTU、路由收敛、网关运行状况和应用综合探测具有阈值。
- [ ] 电路、提供商、边缘、隧道、网关、路由、防火墙、DNS、区域和工作负载故障已在代表性负载下进行了测试。
- [ ] 幸存路径可以承载声明的关键流量，而不会耗尽网关、防火墙、路由或下游容量。
- [ ] 配置通过基础设施即代码进行部署，更改经过审核，并且提供程序、证书、密钥、续订和停用证据是最新的。
- [ ] 仪表板、告警、提供商联系人、升级路径、故障转移、故障恢复和协调操作手册在生产使用前已准备就绪。
